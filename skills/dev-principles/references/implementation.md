## 三、12-Factor App (适用条款)

| Factor | 强度 | 规则 |
|--------|------|------|
| **Config** | MUST | 配置与代码严格分离。环境变量注入，`.env` 不入版本控制。不硬编码 URL、密钥、魔法数字。 |
| **Dependencies** | MUST | 显式声明所有依赖，不依赖系统级隐式包。 |
| **Backing Services** | SHOULD | 数据库、缓存、消息队列作为可替换的附加资源，通过配置切换。 |
| **Logs** | SHOULD | 日志作为事件流，使用结构化日志。 |
| **Dev/Prod Parity** | SHOULD | 开发与生产环境尽可能一致。 |

## 四、Coding Conventions (编码守则)

### 1. 模式一致性

**SHOULD** 同一项目中，相同类型的操作使用相同模式（数据请求、错误处理、表单提交等）。一旦确立模式，所有同类代码遵循。**一致性是对好模式的一致。** 遇到已有模式时，先验证它是否合理，再决定是否跟随。跟随一个错误的模式 ≠ 保持一致性。

### 2. 错误处理

- **MUST** 禁止无说明地静默吞错。若某类异常被设计为可忽略（幂等删除、best-effort telemetry、清理阶段异常等），必须显式注释其业务理由，并视风险选择 debug/warn 级日志、指标上报或受控忽略。
- **SHOULD** 后端：集中异常体系 + 全局处理器，业务异常使用语义化异常类。
- **SHOULD** 前端：全局 Error Boundary + 通知系统，组件级错误降级。
- **MUST** 错误信息对用户有意义，不暴露内部实现。

### 3. 状态与副作用

- **SHOULD** 简单异步操作优先统一为 loading / error / success 三态抽象，不在每个页面重复手写。更复杂交互（流式响应、乐观更新、长轮询、WebSocket）应按实际状态机建模，而不是强行压平成三态。
- **SHOULD** 状态作用域最小化：局部 → 共享（最近公共祖先）→ 全局。

### 4. 认证与安全

- **MUST** 受保护路由/端点在入口处统一拦截，不依赖每个页面/handler 自行检查。
- **SHOULD** 认证状态集中管理，不在多处独立解析 Token。
- **SHOULD** 边界负责完整输入校验；内部模块默认基于契约协作，但对关键不变量（权限、金额、资源归属、状态转换）仍应进行防御性校验。
- **SHOULD** 充分利用类型系统作为第一道防线。

### 5. API 层

- **SHOULD** 外部请求通过统一 API Client 模式治理，集中处理认证头、Token 刷新、错误转换。可按服务域拆分多个 typed client，共享基础能力，不强求单一巨型 client。判断是否需要统一 client 的标准不是项目大小，而是：存在认证 / 需要重试 / 有错误转换需求 / 多处调用同一服务 → 统一；一次性脚本、单个请求 → 不强求。
- **SHOULD** API 函数按模块组织，返回类型化结果。
- **MUST** API 函数不承载业务决策。它们负责请求发送、协议适配、认证注入、错误归一化、类型映射等传输层职责，不负责业务编排。

### 6. 常量集中管理

- **SHOULD** 状态值、错误码等离散常量应使用语言中合适的枚举/字面量联合/常量定义方式集中表达，避免散落魔法字符串。
- **SHOULD** 错误码、业务常量等集中定义在 constants 模块。

### 7. 数据访问与性能

- **MUST** 避免随结果数量增长的逐项关联查询（N+1）。检查 query count，按语义与数据量选择 JOIN、eager loading、批量查询或有界分批；不强制把大结果全部加载到内存 join。
- **SHOULD** 查询只 select 实际使用的列，避免无差别 `SELECT *`，尤其在宽表或包含大文本/JSON/二进制字段时。
- **MUST** 缓存有明确一致性契约和失效责任。要求及时一致时由写路径在成功提交后更新/失效，并处理失效失败、并发回填和外部写入；仅在业务明确接受有界陈旧时可采用 TTL-only，记录最长窗口。不能把过期策略当成强一致保证。
- **MUST** 重试先确认失败可恢复、操作幂等或有去重保障，再设置请求超时、总预算与最大次数。使用带 jitter 的有界指数退避，按服务契约处理 Retry-After；不是所有网络错误/5xx 都可重试，结果未知的写入尤其不能盲重放。避免多层重试叠加。
- **MUST** 跨副本的用户/租户全局配额必须使用共享计数或统一网关；进程内计数只能承诺本进程的并发保护/限流，不能冒充全局额度。明确限流器不可用时 fail-open/fail-closed 的取舍与信号。
